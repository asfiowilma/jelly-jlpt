# Outline (level-author)

Writes the teaching order of one JLPT level. Output: `tools/plan-<level>.js` edited, then `data/<level>/plan.js` regenerated by `tools/author-plan.js`. Never hand-edit `data/<level>/plan.js`.

## Sources to read (only these)

1. `CLAUDE.md`: hard constraints, stable ids, commit rules.
2. `docs/playbook/index.md`, then [docs/playbook/plan.md](../../../docs/playbook/plan.md) (Plan).
3. The header of `tools/author-plan.js` (format of LESSONS rows).
4. `tools/plan-<level>.js` (current state, if it exists).
5. The grammar inventory for the level (e.g. `.scratch/<level>-launch/<level>-grammar-inventory.md`) and `tools/<level>-grammar-notes.md`, for block order.
6. The brief path given by the orchestrator.

Do not read review reports, STATE.md, or other levels' plans except the one named as reference in the brief.

## Write ceiling

- Allowed to edit: `tools/plan-<level>.js`.
- Allowed to run: `node tools/author-plan.js <LEVEL>` (regenerates `data/<level>/plan.js`), `node tools/build-sw.js` (plan.js is a shipped file, so sw.js must be rebuilt and committed).
- Not allowed: `sw.js`, `data/n5/{vocab,kanji,plan,read-words}.js`, `audio/manifest.js`, `kanji-svg/strokes.js`, `data/<level>/plan.js` by hand, `vocab-overrides`, `kanji-overrides`, `grammar.js`, `dialogues`, `mocks`, `mondai`, `index.html`, `CREDITS`, `STATE.md`, `known-issues.md`.
- `GUIDES` and `PREP` are in scope, including the mock unit rows (`x:<level>-mock-<n>`). The mocks skill never edits the plan. A mock row whose `x:` id has no `data/<level>/mocks.js` entry yet is fine; the mocks type fills it.

## Rules

1. Ids are stable. Append new units; never reorder or renumber a unit id that already ships. `READY` stays `false` unless the brief says flip.
2. Each `LESSONS` row: `[title, grammar id(s) or '', vocab tokens, fixed kanji?]`. Grammar ids: space-separated only for close siblings or a short form.
3. Order follows the grammar block order in the inventory. A conjugation form comes before the patterns built on it.
4. Vocab tokens come from the level's catalog only. Use `名|読み` form for a fixed reading. Do not invent words.
5. Lesson titles and notes: our own words, plain English. No copied text from jlpt.jp, JLPT Sensei, NHK, Tofugu.
6. Every catalog id for the level is used by at least one unit (coverage 100%). Report any gap; do not pad with filler.
7. Lesson notes explain in our own words. No raw `g:` or `k:` ids in player-facing text.
8. Japanese facts: from the authority order in CLAUDE.md. Do not ask the owner Japanese questions.

## Steps

1. Read the sources above. Confirm the level's grammar block list.
2. Edit `tools/plan-<level>.js` per the brief. Keep the file header comment short and current.
3. Run `node tools/author-plan.js <LEVEL>`.
4. Run the coverage check and the plan tests: `CLAUDE_PROJECT_DIR=$(pwd) node .claude/hooks/run-tests.js` inside the worktree.
5. Stale audio clips: run the suite with `AUDIO_STALE_OK=1` as the level-author agent says, and list the stale clips in the return message. Never remove the flag.
6. Commit once in the worktree on branch `author-<level>-outline`. Gitmoji subject, imperative, one emoji, no scope. No co-author line.

## Stop and report (do not guess)

- Coverage gap that needs a catalog change.
- Grammar block order unclear in the inventory.
- A unit needs a grammar id that does not exist in `data/<level>/grammar.js`.
- Tests fail after one fix attempt.
- Brief asks for a file outside the write ceiling.

## Output (return message)

- Branch, commit hash.
- Unit count (lessons, reviews), id range added.
- Coverage: x of y catalog ids used.
- Tests: pass/fail, count.
- Stopped at step N with reason, or `done`.

## Does not

Merge, push, force-push, `reset --hard`, delete branches, `--no-verify`, touch other worktrees, spawn sub-agents, flip `READY`, or write player-facing copy outside lesson notes.
